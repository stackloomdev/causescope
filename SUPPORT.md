# CauseScope support

CauseScope is maintained in public on a best-effort basis. Choosing the right channel keeps reports actionable and prevents sensitive application data from being exposed.

## Questions and setup help

Use [GitHub Discussions](https://github.com/stackloomdev/causescope/discussions) for installation questions, configuration help, and early design ideas. Include the CauseScope, React, Vite, Node.js, pnpm, and browser versions involved.

## Reproducible bugs

Use the [bug report form](https://github.com/stackloomdev/causescope/issues/new?template=bug_report.yml) when a problem has a minimal public reproduction. Explain which element was selected, what evidence appeared, and what evidence you expected.

The latest published beta or stable release receives fixes. Older versions may be closed with a request to reproduce on the current release.

## Feature proposals

Start in [Discussions](https://github.com/stackloomdev/causescope/discussions) when the evidence source, privacy boundary, or API shape is still open. Use the feature request form when the problem and acceptance boundary are specific enough to implement.

## Security and private data

Do not post credentials, private source code, customer data, screenshots of private applications, or unredacted trace exports in Issues or Discussions.

Report suspected vulnerabilities through [GitHub private vulnerability reporting](https://github.com/stackloomdev/causescope/security/advisories/new) and follow [SECURITY.md](SECURITY.md).
